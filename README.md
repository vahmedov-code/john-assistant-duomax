# John Assistant — Яндекс Станция Дуо Макс

Версия **0.3** (`moscow.avior.john`, versionCode 3): локальное голосовое управление через Vosk.
Основа — проверенная на станции версия 0.2-test. Её ручные кнопки, AudioManager,
MediaController для `ru.yandex.music` и NotificationListenerService сохранены.

## Как включить голосовое управление

1. Установите APK обновлением, откройте приложение и сохраните доступ к уведомлениям.
2. Нажмите **Скачать модель**. Нужны интернет и не менее 220 МБ свободного места для установки.
   Прогресс виден в приложении; загрузку можно отменить. Если система завершит процесс,
   запустите загрузку повторно. Полностью скачанная модель сохраняется между запусками.
3. Нажмите **Запустить Джона** и разрешите микрофон. Появится уведомление с кнопкой остановки.
4. Дождитесь статуса «Слушаю локально». Скажите одну из фраз ниже.
5. **Остановить Джона** или кнопка в уведомлении освобождает микрофон и память модели.

| Команда | Примеры |
|---|---|
| Громче | «Джон, громче», «Джон, сделай громче», «Джон, увеличь громкость» |
| Тише | «Джон, тише», «Джон, убавь громкость» |
| Выключить звук | «Джон, выключи звук», «Джон, отключи звук» |
| Следующий трек | «Джон, следующий трек», «Джон, следующая песня» |
| Пауза | «Джон, пауза», «Джон, останови музыку», «Джон, поставь на паузу» |

Можно сказать отдельное «Джон», дождаться завершения фразы, затем произнести команду в течение
5 секунд. Обращение разрешает только одну команду. Неизвестная фраза или «отмена» сбрасывает
ожидание. Исполняются только завершённые результаты распознавания; частичные результаты
показываются с многоточием и ничего не выполняют. Фразы с отрицанием отклоняются, если Vosk
их распознал. Распознавание не гарантирует отсутствие ложных срабатываний на музыку/телевизор.
«Выключи звук» всегда отключает звук, а не переключает mute; включить звук можно ручной кнопкой.

## Модель и приватность

Используется [vosk-model-small-ru-0.22](https://alphacephei.com/vosk/models), Apache 2.0,
около 45 МБ в архиве и 87 МиБ после распаковки. Контрольная сумма SHA-256 официального архива:

```text
961d5ff98a17f4aa6de69864d0aa71fa5bac682301d2b5d17a3f24c5c99a46d4
```

Источник: `https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip`.
Сумма вычислена по загруженному HTTPS-архиву 27 октября 2026, а не взята из отдельной
подписанной ведомости поставщика. Клиент сверяет её до распаковки. Изменившийся архив
не устанавливается без обновления закреплённой суммы в коде.

Архив скачивается по HTTPS без произвольных редиректов. Размер загрузки, распакованный размер,
число файлов и пути ограничены. Установка идёт в промежуточную приватную папку; готовая модель
заменяется переименованием, незавершённая распаковка не считается установленной.
Каждый распакованный файл проверяется по SHA-256 перед загрузкой модели в Vosk.
При повреждении остановите Джона и нажмите **Скачать модель заново**.

Модель хранится в `no_backup/vosk/` приложения, исключена из резервного копирования,
не включена в APK или GitHub. Удаление приложения/его данных удалит и модель.
Vosk 0.3.75 и JNA 5.18.1 закреплены в Gradle; Google Play Services не нужны.
После установки модели локальным голосовым командам интернет не нужен. Аудио не пишется
в файл и не отправляется в сеть; последняя фраза и команда живут только в памяти процесса.
Старая дополнительная кнопка системного SpeechRecognizer сохранена и может использовать
облачную службу, если она есть; Vosk от неё не зависит.

## Фоновая служба и перезагрузка

Микрофон запускается пользователем из видимого приложения. Служба имеет тип `microphone`,
разрешения RECORD_AUDIO, FOREGROUND_SERVICE и FOREGROUND_SERVICE_MICROPHONE,
уведомление и частичную блокировку сна CPU только на время прослушивания. Захват — mono PCM
16 кГц, один поток, ограниченный словарь, обновление текста не чаще двух раз в секунду.
Потребление CPU/RAM на Duo Max пока не измерено. Маленькая модель всё равно требует
значимой оперативной памяти; не считайте 45 МБ архива размером потребления RAM.

BOOT_COMPLETED/MY_PACKAGE_REPLACED восстанавливают слушатель медиасессий и показывают
напоминание о ручном запуске, если Джон ранее был включён. Микрофон из receiver не запускается.
Служба START_NOT_STICKY: после завершения системой требуется повторный запуск кнопкой.
Уведомление может быть скрыто настройками YaOS/Android; приложение также показывает подсказку.
См. [ограничения microphone foreground service](https://developer.android.com/develop/background-work/services/fgs/service-types#microphone).

Одновременная запись Vosk и Алисы, поведение при блокировке/сне и перезагрузке реальной
станции требуют проверки. Android может дать тишину или заглушить клиент: приложение
показывает предупреждение о заглушённом входе (API 29+) либо отсутствии ненулевых отсчётов
15 секунд. Это диагностика, а не доказательство, что виновата именно Алиса.
Не отключайте Алису или защиту системы ради проверки. Если YaOS останавливает службу,
технически поддерживаемый вариант этой версии — открыть приложение и нажать запуск.
Экран не удерживается включённым, обход ограничений YaOS не реализован.

## Первый запуск в Windows PowerShell

Нужны Git, Android Studio, JDK 17, Android SDK Platform 34 и Build Tools 34.0.0.
Версии закреплены: Android Gradle Plugin 8.7.3, Gradle 8.9.
Первый запуск скачивает Gradle и зависимости; контрольная сумма Gradle закреплена в wrapper properties.

```powershell
cd "$HOME\AndroidStudioProjects"
git clone https://github.com/vahmedov-code/john-assistant-duomax.git JohnAssistant
cd JohnAssistant
```

Откройте эту папку в Android Studio и укажите JDK 17 в Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK.
Установите SDK Platform 34 и Build Tools 34.0.0 через SDK Manager.
Android Studio создаст локальный `local.properties` с путём к SDK.

В терминале PowerShell выберите JDK 17. На исходном компьютере он установлен здесь:

```powershell
$env:JAVA_HOME = "$HOME\.jdks\jbr-17.0.14"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
"sdk.dir=$($env:ANDROID_HOME.Replace('\','/'))" | Set-Content -Encoding ascii .\local.properties
& "$env:JAVA_HOME\bin\java.exe" -version
.\gradlew.bat assembleDebug
```

Если JDK 17 находится в другой папке, измените JAVA_HOME. Системный JBR Android Studio может быть более новой версии: для этого проекта используйте JDK 17.
APK: `app\build\outputs\apk\debug\app-debug.apk`.
На Linux/macOS: `./gradlew assembleDebug` с JDK 17 и настроенным Android SDK.

## Получение обновлений

Из папки проекта в терминале Android Studio:

```powershell
git status
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Обновление не выполнено. Проверьте сообщение Git.' }
.\gradlew.bat assembleDebug
```

Обычный `git pull` тоже работает: для подготовленной локальной копии включён режим fast-forward only.
Для свежего клона можно включить его один раз: `git config pull.ff only`.
Если истории разошлись, Git остановится и сохранит ваши коммиты.

## Обновление с незакоммиченными правками

Сначала проверьте `git status`, затем сохраните правки, включая новые файлы:

```powershell
git stash push --include-untracked -m "before-update"
```

Убедитесь, что Git сообщил о созданном stash. Если изменений нет, stash не создаётся — не применяйте старые записи автоматически.
Затем:

```powershell
git pull --ff-only
```

При ошибке остановитесь и разберите её. После успешного обновления найдите свою запись:

```powershell
git stash list
git stash apply 'stash@{0}'
git status
```

Используйте индекс именно созданной вами записи. `apply` сохраняет резервную запись stash.
Если возникли конфликты, исправьте отмеченные файлы в Android Studio и проверьте сборку.
Только после проверки можно удалить соответствующую резервную запись: `git stash drop 'stash@{0}'`.
Не используйте `git reset --hard` или `git clean -fd` для обычного обновления.
Игнорируемые настройки и ключи stash не сохраняет — храните их резервную копию отдельно.

Для постоянных доработок заведите ветку: `git switch -c my-changes`.
После проверенных коммитов обновляйте её через `git fetch origin`, затем `git merge origin/main`.
При конфликте исправьте файлы и завершите merge либо отмените его командой `git merge --abort`.

## Подпись и обновление установленного APK

Без `signing.properties` Gradle использует стандартный локальный debug-ключ Android.
Он может отличаться от подписи прежнего APK. При `INSTALL_FAILED_UPDATE_INCOMPATIBLE`
нужен прежний ключ; не удаляйте приложение автоматически, иначе можно потерять его данные.

На компьютере, где подготовлен этот проект, прежний тестовый ключ сохранён локально в
`signing/john-test.keystore`, а параметры — в `signing.properties`. Оба пути исключены из Git.
Это обеспечивает прежнюю тестовую подпись для `assembleDebug`; проверяйте установку на станции.
В новом клоне этих файлов нет. Переносите ключ и параметры отдельно через доверенный канал.
Формат локального `signing.properties`:

```properties
storeFile=signing/your-existing-test.keystore
storePassword=YOUR_LOCAL_PASSWORD
keyAlias=YOUR_ALIAS
keyPassword=YOUR_LOCAL_PASSWORD
```

Этот ключ предназначен для тестов. Release-подпись и публичный выпуск здесь не настроены.
Ключи, пароли, токены, `.env`, APK, архивы и `local.properties` не коммитить.
Перед каждым коммитом проверяйте `git diff --cached` и `git status`.

## Реализованные возможности и ограничения

- Управление медиасессией пакета `ru.yandex.music`: play/pause/next/previous.
- Изменение громкости через Android AudioManager.
- Краткая проверка микрофона через AudioRecord без сохранения звука.
- Голосовая команда по кнопке через системный SpeechRecognizer, если он доступен в YaOS.
- NotificationListenerService и запрос переподключения после загрузки/обновления приложения.

Добавлена служба Vosk с активацией обращением «Джон» после ручного запуска.
Совместная работа микрофона с Алисой требует проверки на станции.
Успешная сборка не доказывает работу всех функций на YaOS.
Минимальная версия Android 8/API 26; compileSdk 34, targetSdk 32 сохранены из тестового проекта.

## Установка обновления через ADB из PowerShell

Собирайте в той же локальной копии и с тем же ключом, которыми собрана установленная 0.2.
Не переносите чужой signing.properties поверх своего. Если 0.2 собиралась стандартным Gradle,
сохраните `%USERPROFILE%\.android\debug.keystore`; он не входит в этот репозиторий.
Установка `-r` сохраняет данные при совместимой подписи. При несовместимости остановитесь;
не выполняйте uninstall и не меняйте ключ автоматически.

```powershell
cd "$HOME\AndroidStudioProjects\JohnAssistant"
git status
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Проверьте ошибку Git; локальные правки сохраняйте по инструкции выше.' }
$env:JAVA_HOME = "$HOME\.jdks\jbr-17.0.14"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
.\gradlew.bat assembleDebug
if ($LASTEXITCODE -ne 0) { throw 'Сборка не выполнена' }
$adb = "$env:ANDROID_HOME\platform-tools\adb.exe"
$station = Read-Host 'Адрес ADB станции с портом, например 192.168.1.50:5555'
& $adb connect $station
& $adb devices -l
# Убедитесь, что это нужная станция и её статус — device.
& $adb -s $station install -r .\app\build\outputs\apk\debug\app-debug.apk
if ($LASTEXITCODE -ne 0) { throw 'Установка не выполнена. Не удаляйте прежнее приложение.' }
& $adb -s $station shell am start -n moscow.avior.john/.MainActivity
```

Если другая версия ADB занимает стандартный сервер, используйте один отдельный порт,
например `& $adb -P 5041 ...`, во всех ADB-командах. Не публикуйте ADB в интернет.

## Проверки разработчика

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug lintDebug
```

Для теста настоящего архива до запуска тестов задайте `JOHN_TEST_MODEL_ARCHIVE` полным путём
к официальному ZIP: тест дополнительно проверит закреплённый SHA-256, распаковку и каждый файл.
Без переменной этот один тест пропускается; архив не нужен для обычной сборки.

`VoiceSmokeInstrumentation` в androidTest предназначен только для отдельного эмулятора:
передайте ZIP как `model.zip` в external files приложения, разрешите микрофон и установите
тестовый APK (`assembleDebugAndroidTest`), затем выполните:

```text
adb -s EMULATOR_SERIAL shell am instrument -w moscow.avior.john.test/moscow.avior.john.VoiceSmokeInstrumentation
```

Тест заменяет модель в тестовом приложении, проверяет native Vosk, AudioRecord, работу после
сворачивания Activity, остановку/повторный запуск и отсутствие старта микрофона из BootReceiver.
Не запускайте этот тест на рабочей станции: это тестовая подготовка данных, не установка обновления.
Фактические результаты и список проверок Duo Max описаны в [docs/verification-0.3.md](docs/verification-0.3.md).

Сведения о сторонних компонентах: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
